쿠버네티스를 배우려고 검색하면 나오는 글은 대개 두 종류입니다. 하나는 노트북에 minikube를 깔아 보는 글이고, 다른 하나는 회사에서 이미 돌고 있는 클러스터를 전제하는 글입니다. 그런데 앞쪽은 실제 클라우드가 아니라서 네트워크도 스토리지도 흉내만 내고, 뒤쪽은 클러스터를 만들어 보는 경험 자체를 건너뜁니다.


그 사이가 비어 있습니다. 직접 세워 보고는 싶은데 AWS는 켜는 순간부터 돈이 나가고, 얼마가 나갈지 모르는 상태에서는 `apply`를 누를 용기가 좀처럼 생기지 않습니다. 저도 한동안 그 자리에서 망설였습니다.


이 시리즈는 그 빈칸을 신규 계정 크레딧 \$200으로 메웁니다. 열두 편을 따라가면 VPC부터 HTTPS 인증서까지 전부 직접 세운 클러스터가 손에 남는데, 그동안 클러스터를 켜 두는 시간은 다 합쳐 여덟 시간 반이면 됩니다. 시간당 얼마가 나가는지만 알면 자기 비용은 거기서 계산할 수 있으므로, 이번 편은 그 단가표를 만드는 데 씁니다.


이번 편에는 코드가 없습니다. 대신 무엇을 만들 것인지와 돈이 정확히 어디서 나가는지를 먼저 봅니다. 이 두 가지를 모르고 덤비면 아예 시작을 못 하거나, 시작하고 나서 겁이 나 중간에 멈추게 되기 때문입니다.

> 쿠버네티스를 클라우드에서 배우는데 돈을 얼마나 써야 하는가?

## EKS는 쿠버네티스를 대신 운영해 주는 서비스입니다


본론에 들어가기 전에 용어부터 정리하겠습니다. 이미 아시는 분은 이 절을 건너뛰셔도 됩니다.


쿠버네티스(Kubernetes)는 컨테이너를 여러 서버에 나눠 돌려 주는 프로그램입니다. 컨테이너를 직접 서버에 올리면 어느 서버에 몇 개를 띄울지, 죽으면 누가 다시 띄울지를 사람이 전부 정해 줘야 합니다. 반면 쿠버네티스에는 "이 앱을 2개 띄워 둬"라고 선언만 하면 됩니다. 나머지는 쿠버네티스가 그 상태를 알아서 유지합니다.


이 프로그램은 두 부분으로 나뉩니다. 명령을 받고 상태를 결정하는 **컨트롤플레인**과, 실제로 컨테이너가 돌아가는 서버인 **노드**입니다. 공항에 비유하면 컨트롤플레인이 관제탑이고 노드가 활주로입니다.


```plain text
kubectl ──►  ┌───────────────────────────────┐
             │  컨트롤플레인                   │   관제탑
             │  API 서버 · 스케줄러 · etcd     │   EKS 에서는 AWS 가 운영합니다
             └───────────────┬───────────────┘
                             │  "이 상태를 유지해라"
             ┌───────────────▼───────────────┐
             │  노드                          │   활주로
             │  [ 앱 Pod ]     [ DB Pod ]     │   내가 고르고 내가 냅니다
             └───────────────────────────────┘
```


쿠버네티스를 직접 설치하면 관제탑도 내 손으로 세워야 합니다. 서버 세 대에 etcd를 띄우고, 인증서를 발급하고, 버전 업그레이드까지 직접 챙겨야 하는 일입니다. 그러다 보니 쿠버네티스를 배우려던 사람이 쿠버네티스 설치를 배우다가 지치는 경우가 많습니다.


EKS(Elastic Kubernetes Service)는 그 관제탑을 AWS가 대신 운영해 주는 서비스입니다. 노드는 내가 고르고 컨트롤플레인은 AWS가 맡습니다. 덕분에 배우는 입장에서는 쿠버네티스를 쓰는 법에 집중할 수 있고, 대신 관제탑 사용료를 냅니다. 이 사용료가 뒤에서 가장 중요한 숫자가 됩니다.

> **ECS와 뭐가 다른가요**
> 
> AWS에는 ECS라는 비슷한 서비스가 있고 더 싸고 쉽습니다. 다만 ECS는 쿠버네티스가 아닙니다. AWS가 따로 만든 것이라 `kubectl`도 Pod도 매니페스트도 없습니다. 개념이 대응되는 물건은 있지만, 쿠버네티스를 배우려는 목적이라면 옮겨 쓸 수 있는 것이 거의 없습니다. 이 시리즈가 더 비싸고 더 느린 EKS를 쓰는 이유입니다.

## 돈은 세 군데서 나갑니다


여기가 이번 편의 핵심입니다. EKS가 무섭게 느껴지는 이유는 요금표가 복잡해서가 아니라고 생각합니다. 무엇을 켜면 돈이 나가는지 모르는 상태이기 때문입니다. 지도를 먼저 그려야 하는 이유입니다. 아래는 서울 리전 기준의 단가입니다.


| 무엇                       | 시간당       | 한 달 켜 두면 | 끌 수 있나              |
| ------------------------ | --------- | -------- | ------------------- |
| **EKS 컨트롤플레인**           | **\$0.10** | **\$73**  | 클러스터를 **지워야만** 멈춥니다 |
| ALB (로드밸런서) 세트           | \$0.0405   | \$29.6    | Ingress를 지우면 멈춥니다   |
| EC2 노드 `t4g.small` 1대    | \$0.0208   | \$15.2    | 대수를 0으로 줄이면 멈춥니다    |
| 노드 퍼블릭 IP 1개             | \$0.005    | \$3.65    | 노드와 함께              |
| EBS 볼륨 10GB              |           | \$0.91    | **클러스터를 지워도 남습니다**  |
| S3, DynamoDB, IAM, 예산 알림 |           | ~\$0      | 계속 켜 둬도 됩니다         |


이 표에서 기억할 것은 세 가지입니다. 첫째로 가장 비싼 것은 노드가 아니라 컨트롤플레인입니다. 노드를 한 대도 띄우지 않아도 시간당 \$0.10이 꼬박꼬박 나갑니다. 한 달을 켜 두면 \$73이니, 크레딧 \$200의 3분의 1이 여기서 사라지는 셈입니다.


둘째로 노드를 줄이는 것으로는 요금을 막을 수 없습니다. 클라우드 비용을 아끼는 기본 수단은 인스턴스를 줄이는 것입니다. 그런데 여기서는 노드를 전부 0으로 내려도 컨트롤플레인과 로드밸런서가 그대로 돌아서 월 \$102가 계속 나갑니다. 위 표의 구성으로 계산하면 시간당 \$0.1663 가운데 \$0.1405, 즉 84%가 노드와 무관한 고정비입니다. 아래 그림에서 하나씩 꺼 보면 이 점이 더 잘 보입니다.


![Anim.1 — 노드를 0대로 줄여도 요금의 84%가 그대로 나가고, 클러스터를 지워야 0이 됩니다. 숫자는 위 표와 같고, 그림은 AI가 코드로 그렸습니다](https://dhbang.co.kr/images/aws-eks/anim01-cost-states.svg)


셋째로 볼륨은 클러스터보다 오래 삽니다. 데이터를 담아 두는 EBS 볼륨은 일부러 클러스터 밖에 두기 때문에, 클러스터를 지워도 월 \$0.91이 계속 나갑니다. 금액은 작습니다. 하지만 "다 지웠는데 왜 돈이 나가지"라는 의문이 들 때 범인은 대개 이것입니다.

## 그래서 규율은 하나입니다. 쓸 때만 켭니다


고정비가 84%라는 말을 뒤집으면, 꺼져 있는 동안에는 정말로 \$0이라는 뜻이 됩니다. 이 시리즈가 처음부터 끝까지 한 가지 방식으로 가는 이유입니다. 실습을 시작할 때 `tofu apply`로 클러스터를 만들고, 끝나면 `tofu destroy`로 지웁니다. 실습과 실습 사이에는 클러스터가 아예 존재하지 않는 것입니다.


처음에는 번거롭게 들릴 것입니다. 클러스터를 만드는 데 10분쯤 걸리니 매번 10분을 버리는 셈이기 때문입니다. 하지만 비용을 계산해 보면 생각이 바뀝니다.


```plain text
클러스터를 처음부터 다시 만들기   약 $0.07
4시간 실습 한 번                 약 $0.64
하루 종일(8시간) 삽질             약 $1.28
```


다시 만드는 값이 7센트라는 것은 망쳐도 7센트라는 뜻입니다. `apply`가 깨져서 전부 지우고 다시 세워도 커피 한 잔의 100분의 1이 안 됩니다. 이 시리즈에서는 마음껏 부수셔도 됩니다. 정작 아껴야 하는 것은 크레딧이 아니라 켜 놓고 딴짓하는 시간입니다.

> **Terraform이 아니라 OpenTofu를 씁니다**
> 
> 이 시리즈는 콘솔 클릭 없이 전부 코드로 만듭니다. 그 도구가 Terraform에서 갈라져 나온 오픈소스 버전인 OpenTofu이고, 명령어와 문법이 거의 같아서 `tofu`를 `terraform`으로 바꿔 읽어도 대부분 동작합니다. 코드로 만드는 이유는 자동화가 아니라 반복과 삭제입니다. 켜고 끄기를 수십 번 해야 하는데 콘솔 클릭으로는 그것을 감당할 수 없기 때문입니다.

## \$200로 실제로 얼마나 할 수 있나


앞에서 본 표가 단가입니다. 여기에 내가 켜 둔 시간을 곱하면 내 청구서가 나옵니다. 그런데 컨트롤플레인은 아무 일을 하지 않아도 시간당 \$0.10으로 일정합니다. 거꾸로 청구액을 0.1로 나누면 클러스터를 켜 둔 시간이 그대로 나옵니다. 이 방법으로 제 기록을 계산해 보면 다음과 같습니다.


| 켠 이유        | 시간         | 컨트롤플레인 요금 |
| ----------- | ---------- | --------- |
| 실습하려고 켠 시간  | 8.4h       | \$0.84     |
| 끄는 걸 잊은 하룻밤 | **17.3h**  | **\$1.73** |
| **가동 합계**   | **25.75h** | **\$2.58** |


실습한 시간보다 잊어버린 시간이 두 배 많습니다. 어느 날 `destroy`가 중간에 멈춘 것을 확인하지 않고 잠들었는데, 아침에 보니 클러스터가 그대로 돌고 있었습니다. 이 밤에 대해서는 ⑫편에서 자세히 다루겠습니다. 한편 클러스터 밖에서도 돈이 나갔습니다.


| 항목                          | 누적        | 성격                                |
| --------------------------- | --------- | --------------------------------- |
| EBS 볼륨 등                    | \$2.14     | **기간에 비례합니다.** 두 달 넘게 세워 둔 주차비입니다 |
| VPC · ECR · RDS · ALB · 시크릿 | \$0.89     | 일부는 가동분, 일부는 보관분입니다               |
| 비용을 조회한 API 호출              | \$0.26     | 제가 제 청구서를 들여다본 값입니다               |
| **총 지출**                    | **\$5.87** | 크레딧 \$200의 **2.9%**                |


정리하면 실습 자체로 쓴 돈은 \$1 남짓입니다. 나머지는 사고 한 번과 두 달치 주차비, 그리고 제가 비용을 조회하느라 쓴 값입니다. 이 가운데 어느 것도 독자가 그대로 물려받는 값은 아닙니다. 독자가 물려받는 것은 앞에서 본 단가표입니다.


크레딧이 모자랄 걱정은 하지 않으셔도 됩니다. 끄는 것만 잊지 않으면 완주에 \$1 안팎이 들고, 제 \$5.87은 그것을 한 번 잊었을 때 어디까지 갈 수 있는지를 보여 주는 숫자입니다. ③편에서는 알림을 걸고 ⑫편에서는 자동으로 끄는 장치를 만듭니다. 그 두 편이 존재하는 이유가 바로 저 하룻밤입니다.

## 어디서 비싸지는가


이 시리즈가 모든 것을 가르쳐 주지는 않습니다. 시작하기 전에 알아 두시면 좋은 한계를 적어 둡니다.


우선 이것은 프로덕션 구성이 아닙니다. 노드를 가용 영역 한 곳에 몰아 두고, NAT 게이트웨이를 쓰지 않고, 데이터베이스를 클러스터 안에 둡니다. 전부 비용을 줄이기 위한 선택이라서 실제 서비스라면 다르게 해야 합니다. 각 편에 실제 운영이라면 어떻게 달라지는지를 따로 적어 두겠습니다.


그리고 상시 켜 두는 구성은 다루지 않습니다. 이 시리즈의 전제가 쓸 때만 켜는 것이기 때문입니다. 참고로 24시간 돌리면 앞의 단가표 그대로 월 \$121이 나가고, 크레딧은 7주면 사라집니다. 이 계산은 ⑫편에서 다시 다룹니다.


또한 AWS 콘솔 사용법은 거의 나오지 않습니다. 전부 코드와 명령어로 진행하기 때문입니다. 화면 캡처가 한 장도 없는 것도 같은 이유인데, AWS 콘솔 화면은 자주 바뀌어서 캡처가 코드보다 빨리 낡습니다. 클릭으로 하는 법을 찾으시는 분께는 이 시리즈가 맞지 않습니다.


마지막으로 이 시리즈는 쿠버네티스 입문서가 아닙니다. Pod나 Deployment 같은 개념은 처음 나올 때 설명하지만, 체계적으로 배우는 것이 목적이라면 공식 문서를 함께 보시는 편이 좋습니다.

## 정리


| 알아 둘 것     | 내용                                               |
| ---------- | ------------------------------------------------ |
| EKS가 뭔가    | 쿠버네티스의 관제탑을 AWS가 대신 운영해 주는 서비스입니다                |
| 돈이 어디서 나가나 | 컨트롤플레인 시간당 \$0.10이 가장 크고, 요금의 84%가 노드와 무관한 고정비입니다 |
| 왜 매번 지우나   | 꺼 두면 진짜로 \$0이고, 다시 만드는 비용이 \$0.07이라 망쳐도 괜찮습니다      |
| 얼마 드나      | 클러스터를 여덟 시간 반 켜 두면 완주합니다. \$1 안팎이고, 잊으면 그만큼 늘어납니다 |
| 뭘 조심하나     | 계정 만들 때 조직을 만들면 **크레딧이 즉시 만료**됩니다                |


처음 질문으로 돌아가면, 쿠버네티스를 클라우드에서 배우는 데 드는 돈은 \$1 남짓입니다. 생각보다 적은 것은 요금이 싸서가 아니라 켜 두는 시간을 짧게 만들 수 있기 때문입니다. 제가 \$5.87을 쓴 것은 그 시간을 짧게 만드는 데 한 번 실패했기 때문입니다.

> 클라우드 비용은 무엇을 켜느냐보다 **얼마나 오래 켜 두느냐**가 정합니다.

②편에서는 도구를 설치하고 AWS 계정을 준비합니다. 거기서도 돈은 나가지 않습니다.
