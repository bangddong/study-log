> **AWS 프리티어 \$200으로 EKS 실습하기 ②** · 💰 이 편도 돈이 나가지 않습니다. 비용 **\$0**

튜토리얼에서 계정 만들기는 보통 한 줄로 지나갑니다. _"AWS 계정을 생성합니다"_ 라고 쓰고 다음 장으로 넘어가는데, 실제로 해 보면 그 한 줄 안에 선택지가 여러 개 들어 있고 그중 하나는 **\$200 크레딧을 그 자리에서 전부 태웁니다.**


저는 그 버튼을 누르기 직전에 멈췄습니다. 확인 화면의 안내문을 읽다가 발견했고, 읽지 않았으면 시리즈가 2편에서 끝났을 것입니다.


이번 편에서는 도구 네 개를 깔고 AWS 계정을 쓸 수 있는 상태로 만듭니다. 돈은 나가지 않지만 **돈을 잃을 수 있는 유일한 편**이라서, 순서를 지켜 주시기 바랍니다.

> 계정을 만드는 첫날에 크레딧을 전부 잃을 수 있다.

---


## 도구는 네 개면 충분하고, 전부 공짜입니다


전 과정을 코드로 합니다. 콘솔에서 클릭하는 절차가 없으므로 필요한 것은 명령줄 도구뿐입니다.


| 도구           | 검증한 버전  | 하는 일              | 처음 쓰는 편 |
| ------------ | ------- | ----------------- | ------- |
| **OpenTofu** | v1.12.4 | 인프라를 코드로 만들고 지웁니다 | ③       |
| **AWS CLI**  | 2.36.2  | AWS에 명령을 보냅니다     | ②       |
| **kubectl**  | v1.36.3 | 쿠버네티스에 명령을 보냅니다   | ⑤       |
| **Helm**     | v4.2.3  | 쿠버네티스용 패키지를 설치합니다 | ⑧       |


macOS라면 한 줄입니다.


```bash
brew install opentofu awscli kubectl helm
```


**OpenTofu(오픈토푸)는 Terraform에서 갈라져 나온 도구**입니다. 2023년에 Terraform의 라이선스가 바뀌면서 그 직전 버전을 기반으로 만들어진 것이라, 문법과 명령어가 거의 같고 Terraform 문서를 그대로 보셔도 됩니다. 이 시리즈가 OpenTofu를 쓰는 이유는 라이선스가 완전한 오픈소스이기 때문이고, `terraform`을 이미 쓰고 계신다면 명령어만 바꿔 읽으셔도 전부 동작합니다.


### 🔴 도구 공백은 준비 단계가 아니라 과금 중에 드러납니다


이걸 지금 강조하는 이유가 있습니다. 저는 같은 실수를 **두 번** 했습니다. 클러스터를 띄워 놓고 다음 명령을 치려는 순간 `kubectl`이 없다는 걸 알았고, 몇 주 뒤에는 같은 자리에서 `helm`이 없었습니다.


클러스터는 그동안에도 시간당 요금을 받습니다. 설치하고 PATH를 잡는 몇 분이 그대로 청구서에 올라가는데, 금액 자체는 몇 센트라 아깝지는 않지만 **급할 때 설치하면 버전을 확인하지 않게 되는 것**이 진짜 문제입니다.


과금이 시작되기 전인 지금, 한 줄로 전부 확인합니다.


```bash
command -v tofu kubectl aws helm && aws sts get-caller-identity
```


네 경로가 모두 찍히고 마지막에 계정 정보가 나오면 준비가 끝난 것입니다. 아직 `aws configure`를 하지 않으셨다면 마지막 명령은 실패하는데, 정상입니다. 아래에서 합니다.

> `kubectl`은 클러스터의 쿠버네티스 버전과 맞춰 두면 경고가 줄어듭니다. 이 시리즈는 둘 다 1.36입니다.

## 크레딧 \$200은 한 덩어리가 아니라 여섯 조각입니다


신규 계정을 만들면 크레딧이 들어오는데, _"가입하면 \$200"_ 이 아니라 기본분과 활동분이 나뉘어 있어서 전부 받으려면 콘솔에서 몇 가지를 더 해야 합니다.


제 계정의 실제 구성입니다.


| 출처                | 금액       | 조건                                           |
| ----------------- | -------- | -------------------------------------------- |
| AWS Free Tier 기본  | \$100     | 계정 생성 시 자동                                   |
| Explore AWS 활동 ×5 | \$100     | EC2 · Bedrock · Lambda · Budgets · RDS 각 \$20 |
| **합계**            | **\$200** | 전 건 만료일 동일                                   |


활동분은 콘솔의 안내를 따라 해당 서비스를 한 번씩 건드리면 지급됩니다. 몇 분이면 끝나고, 끄는 것만 잊지 않으면 완주에 \$1 안팎이 드니 사실 \$100만으로도 한참 남습니다. 그래도 받아 두시는 편이 낫습니다. ①편에 적었듯 저는 한 번 잊어서 하룻밤에 그 두 배를 더 썼습니다.


🔴 **만료일을 지금 적어 두세요.** 제 경우 전 건이 **2027-01-15**에 한꺼번에 만료됩니다. 가입일로부터 약 6개월이라, 느긋하게 하다가는 크레딧이 남은 채로 사라집니다.


### RDS 프리티어는 이제 없습니다


예전 글을 보고 오신 분들이 가장 많이 걸리는 자리입니다. _"프리티어니까 작은 DB는 공짜"_ 라고 알고 계실 텐데, **2025년 7월 이후에 만든 계정은 프리티어가 아니라 크레딧 구조**입니다.


```bash
aws freetier get-free-tier-usage
```


이 명령으로 확인했고, RDS는 할인 없이 단가가 그대로 나갑니다. 공짜 항목이 사라진 대신 현금처럼 쓰는 크레딧을 받은 것이라, **어떤 서비스를 쓰든 똑같이 차감된다**고 생각하시면 맞습니다.


이 차이는 ⑨편에서 실제 선택으로 이어집니다. 관리형 RDS 대신 클러스터 안에 Postgres를 직접 띄우는데, 그 판단의 출발점이 여기입니다.

## 🔴 로그인 방식을 고르는 화면에서 크레딧이 사라집니다


여기가 이번 편의 핵심입니다.


계정을 만들고 나면 루트 계정으로 계속 쓰면 안 된다는 안내를 받습니다. 맞는 말이고, 그래서 자격증명 방식을 고르게 되는데 AWS가 요즘 권하는 것은 **IAM Identity Center**입니다. 검색해도 이쪽이 먼저 나오고, 콘솔에도 큼직한 Enable 버튼이 있습니다.


저도 눌렀습니다. 그리고 확인 화면에서 이 문장을 봤습니다.

> Creating an organization automatically upgrades your account from a free plan to a paid plan with a pay-as-you-go pricing and **your free tier credits expire immediately.**

조직(Organizations)을 만들면 계정이 무료 플랜에서 유료 플랜으로 **자동 승격**되고, **프리티어 크레딧은 즉시 만료**된다는 뜻입니다.


IAM Identity Center는 내부적으로 AWS Organizations를 필요로 합니다. 그래서 Identity Center를 켜는 행위가 조직 생성을 동반하고, 조직 생성이 무료 플랜 이탈을 뜻하므로, **결과적으로 로그인 방식 하나를 고른 것이 \$200을 태웁니다.**


```plain text
IAM Identity Center 켜기
       │
       ▼
AWS Organizations 생성  ← 자동으로 따라옵니다
       │
       ▼
Free plan ──► Paid plan 승격
       │
       ▼
🔴 크레딧 즉시 만료
```


**버그가 아닙니다.** 크레딧은 무료 플랜에 딸린 혜택이라, 유료 플랜으로 올라가면 근거가 사라지는 것이 설계대로의 동작입니다. 문제는 그 인과가 **Enable 버튼에서 두 단계 떨어져 있어서** 보이지 않는다는 데 있습니다.


⚠️ **Identity Center 랜딩 페이지의 기본 Enable 버튼도 같은 경로로 이어집니다.** 확인 화면까지 가지 말고, 이 시리즈를 하는 동안에는 Identity Center를 켜지 마시기 바랍니다.


### 그래서 IAM 사용자와 액세스 키를 씁니다


조직을 만들지 않는 방법으로 돌아갑니다. 모범 사례는 아니지만 **학습 전용 계정에서는 크레딧 리스크가 0**이라는 점이 더 중요합니다.


콘솔에서 IAM 사용자를 하나 만들고 `AdministratorAccess`를 붙인 뒤, 액세스 키를 발급받아 로컬에 넣습니다.


```bash
aws configure
```


```plain text
AWS Access Key ID     [None]: <발급받은 키>
AWS Secret Access Key [None]: <발급받은 시크릿>
Default region name   [None]: ap-northeast-2
Default output format [None]: json
```


리전은 서울(`ap-northeast-2`)로 맞춰 주세요. 이 시리즈의 모든 비용 수치가 서울 리전 기준입니다.


권한을 전부 주는 것이 마음에 걸리실 수 있는데, 이 계정은 **학습 전용이고 실제 서비스가 올라가지 않습니다.** 권한을 좁히려면 EKS·VPC·IAM·ECR·ACM에 걸쳐 수십 개 액션을 일일이 허용해야 하고, 그러다 막히면 원인이 권한인지 코드인지 구분하는 데 시간을 다 씁니다. 배우려는 대상이 IAM 정책 설계가 아니라면 여기서 아끼지 않는 편이 낫습니다.


🔴 **다만 이 키는 실제 비밀번호와 같습니다.** 코드에 적지 말고, 커밋하지 말고, 어딘가에 붙여넣지 마세요. `~/.aws/credentials`에만 있어야 합니다. ③편에서 GitHub Actions를 붙일 때는 키 대신 OIDC로 바꾸고 이 키는 폐기합니다.


확인합니다.


```bash
aws sts get-caller-identity
```


```json
{
  "UserId": "AIDA...",
  "Account": "123456789012",
  "Arn": "arn:aws:iam::123456789012:user/bootstrap-admin"
}
```


`Arn` 끝에 방금 만든 사용자 이름이 보이면 됩니다.

## 잔액을 잘못 조회하면 "아직 안 썼네"로 읽힙니다


크레딧이 얼마나 남았는지는 앞으로 계속 보게 되는데, 평범하게 조회하면 **거의 항상 \$0에 가까운 숫자**가 나오고 저는 처음에 이걸 _"아직 아무것도 안 썼구나"_ 로 읽었습니다.


이유는 간단합니다. 사용액과 크레딧 차감액이 같은 달에 **서로 상계**되기 때문입니다. \$0.33을 쓰면 크레딧에서 \$0.33이 빠지므로 순액은 \$0.00000004 같은 값이 됩니다. 숫자는 맞지만 알고 싶던 것이 아닙니다.


둘을 분리해서 봐야 합니다.


```bash
aws ce get-cost-and-usage --time-period Start=2026-07-01,End=2026-07-29 \
  --granularity MONTHLY --metrics UnblendedCost \
  --filter '{"Dimensions":{"Key":"RECORD_TYPE","Values":["Usage","Credit"]}}' \
  --group-by Type=DIMENSION,Key=RECORD_TYPE
```


```plain text
Usage    0.3282654451
Credit  -0.3282654047
```


위가 실제로 쓴 금액이고 아래가 크레딧에서 빠진 금액입니다. 보고 싶은 것은 `Usage` 쪽입니다.

> `RECORD_TYPE`으로 나누지 않으면 두 값이 합쳐져 순액만 나옵니다. **\$200을 얼마나 썼는지 보려면 반드시 이 필터를 넣으세요.**

## 이 편에서 하지 않은 것


준비가 끝났다고 해서 안전해진 것은 아닙니다. 지금 상태에서 콘솔을 잘못 누르면 **아무 알림 없이** 돈이 나가기 시작합니다.


| 없는 것     | 어떻게 되나                 | 언제 |
| -------- | ---------------------- | -- |
| 예산 알림    | 다 쓸 때까지 아무도 알려 주지 않습니다 | ③  |
| 이상 지출 탐지 | 평소의 10배가 나가도 모릅니다      | ③  |
| 자동 정리    | 켜 둔 것을 켜 둔 채로 잊습니다     | ⑫  |


다음 편이 ④편의 네트워크가 아니라 ③편의 가드레일인 것은 그 때문입니다. **첫 과금은 ⑤편**이고, 그 사이 두 편을 전부 안전장치에 씁니다. 순서를 바꾸고 싶어지실 텐데, 저는 이 순서를 지키지 않았다가 ③편 내용을 급하게 뒤에 끼워 넣었습니다.


액세스 키를 쓰는 지금 방식도 **임시입니다.** 키는 유출되면 끝이고 만료도 되지 않으므로, 혼자 로컬에서 쓰는 동안만 허용할 만한 타협입니다. ③편에서 GitHub Actions가 들어오는 순간 OIDC로 바꾸고 키를 지웁니다.

## 정리


| 한 것                   | 확인 방법                              |
| --------------------- | ---------------------------------- |
| 도구 네 개 설치             | `command -v tofu kubectl aws helm` |
| 크레딧 구성 파악             | 기본 \$100 + 활동 \$20×5, 만료일 기록         |
| 🔴 Identity Center 회피 | 켜지 않은 상태 유지                        |
| IAM 사용자 자격증명          | `aws sts get-caller-identity`      |
| 잔액 조회법                | `RECORD_TYPE`으로 Usage와 Credit 분리   |


가장 비싼 실수가 가장 싼 단계에 숨어 있습니다. 이번 편은 돈이 한 푼도 나가지 않지만, **\$200을 통째로 잃을 수 있는 유일한 편**이었습니다.


다음 편에서는 예산 알림과 이상 지출 탐지를 **콘솔이 아니라 코드로** 만듭니다. 콘솔로 하면 3분이면 끝나는 일을 굳이 코드로 하는 이유도 함께 다룹니다.
