> **AWS 프리티어 \$200으로 EKS 실습하기 ②** · 💰 이 편도 돈이 나가지 않습니다. 비용 **\$0**

튜토리얼에서 계정 만들기는 보통 한 줄로 지나갑니다. "AWS 계정을 생성합니다"라고 쓰고 바로 다음 장으로 넘어가는 식입니다. 그런데 그 한 줄을 실제로 따라 해 보면 로그인 방식은 무엇으로 할지, 권한은 어디까지 줄지 같은 선택지가 화면마다 나옵니다. 대부분은 무엇을 골라도 나중에 바꿀 수 있습니다. 하지만 그중 하나에는 크레딧 \$200이 즉시 만료된다는 경고가 붙어 있고, 한 번 지나가면 되돌릴 수 없습니다.


저는 그 선택지를 고르려고 마지막 확인 화면까지 갔다가, 버튼을 누르기 직전에 멈췄습니다. 확인 화면에 적힌 안내문을 끝까지 읽은 덕분인데, 평소처럼 읽지 않고 넘겼다면 이 시리즈는 2편에서 끝났을지도 모릅니다. 이번 편은 돈이 한 푼도 나가지 않지만, 시리즈 전체에서 가장 조심해야 하는 편이기도 합니다.


이번 편에서는 도구 네 개를 설치하고, AWS 계정을 명령줄에서 쓸 수 있는 상태로 만듭니다. 어려운 내용은 없지만 순서가 중요하므로, 계정을 만들기 전에 끝까지 한 번 읽어 보시기를 권합니다.

> 계정을 만드는 첫날에 크레딧을 전부 잃을 수 있다.

---


## 도구는 네 개면 충분하고, 전부 공짜입니다


이 시리즈는 계정을 준비하는 이번 편을 빼면 콘솔에서 클릭할 일이 거의 없습니다. 모든 것을 코드와 명령으로 만들기 때문에, 준비물은 명령줄 도구 네 개가 전부입니다. 아래 표의 버전은 제가 처음부터 끝까지 실제로 사용한 조합입니다.


| 도구           | 검증한 버전  | 하는 일              | 처음 쓰는 편 |
| ------------ | ------- | ----------------- | ------- |
| **OpenTofu** | v1.12.4 | 인프라를 코드로 만들고 지웁니다 | ③       |
| **AWS CLI**  | 2.36.2  | AWS에 명령을 보냅니다     | ②       |
| **kubectl**  | v1.36.3 | 쿠버네티스에 명령을 보냅니다   | ⑤       |
| **Helm**     | v4.2.3  | 쿠버네티스용 패키지를 설치합니다 | ⑧       |


macOS라면 한 줄로 설치할 수 있습니다. Linux나 WSL을 쓰신다면 글 끝의 참고에 있는 각 도구의 설치 문서를 따라 주세요.


```bash
brew install opentofu awscli kubectl helm
```


이 가운데 OpenTofu(오픈토푸)는 낯선 분이 많을 것 같습니다. OpenTofu는 Terraform에서 갈라져 나온 도구입니다. 2023년에 Terraform의 라이선스가 바뀌자 그 직전 버전을 기반으로 만들어졌고, 그래서 문법과 명령어가 거의 같습니다. Terraform 문서를 그대로 참고하셔도 되고, 이미 `terraform`을 쓰고 계신다면 명령어만 바꿔 읽으셔도 전부 동작합니다.


### 도구가 빠졌다는 사실은 미리 확인해야 드러납니다


그런데 ⑤편에서나 쓸 `kubectl`을 왜 필요할 때가 아니라 지금 설치할까요? 저는 필요할 때 설치하려다가 같은 일을 두 번 겪었습니다. 클러스터를 처음 띄우기 직전에 점검하다가 `kubectl`이 없다는 것을 알았고, 나흘 뒤에는 다음 단계를 준비하다가 `helm`이 없다는 것을 알았습니다.


두 번 다 클러스터를 띄우기 전이어서 다행이었습니다. 만약 클러스터를 띄운 뒤에 알았다면 어땠을까요? 클러스터는 제가 도구를 설치하는 동안에도 시간당 요금을 받습니다. 몇 분의 요금은 몇 센트에 불과하지만, 요금이 나가고 있다는 생각에 서두르다 보면 버전을 확인하지 않고 설치하게 됩니다. 그래서 과금이 시작되기 전인 지금, 네 개가 다 있는지를 한 줄로 확인해 둡니다.


```bash
command -v tofu kubectl aws helm && aws sts get-caller-identity
```


네 개의 경로가 모두 찍히고 마지막에 계정 정보가 나오면 준비가 끝난 것입니다. 다만 아직 계정을 연결하지 않으셨다면 마지막 명령은 실패하는데, 지금은 그게 정상입니다. 계정 연결은 이 편의 뒤쪽에서 하므로 그때 다시 실행해 보시면 됩니다. 참고로 `kubectl`은 클러스터의 쿠버네티스 버전과 맞춰 두면 경고가 줄어들고, 이 시리즈는 둘 다 1.36입니다.

## 크레딧 \$200은 한 덩어리가 아니라 여섯 조각입니다


도구가 준비됐으니 계정을 만들 차례입니다. 신규 계정에는 크레딧 \$200이 지급된다고 알려져 있습니다. 그러면 계정을 만든 뒤 크레딧 화면에는 \$200 한 줄이 보일까요? 제 계정에는 여섯 줄이 있었습니다.


한 줄은 AWS Free Tier라는 이름의 \$100이고, 나머지 다섯 줄은 Explore AWS 활동이라는 이름으로 \$20씩입니다. 다섯 가지 활동은 EC2 인스턴스, Bedrock, Lambda, 예산 만들기, RDS였습니다. 이 가운데 예산 만들기는 ③편에서 어차피 하게 되는 일입니다. 제 경우에는 계정을 만든 날에 여섯 줄이 전부 사용 가능 상태였지만, 활동 크레딧이 지급되는 조건은 계정마다 다를 수 있습니다. 그러니 콘솔의 크레딧 화면에서 여섯 줄의 합이 \$200인지를 직접 확인해 보시기 바랍니다.


혹시 \$100만 들어와 있더라도 이 시리즈를 진행하는 데는 문제가 없습니다. ①편에서 계산했듯이 한 달 안에 끝낸다면 드는 돈이 \$3 안쪽이기 때문입니다. 저는 클러스터를 끄는 것을 한 번 잊어서 하룻밤에 \$2 가까이를 더 썼는데, 그런 일을 겪어도 한참 남습니다.


만료일도 지금 바로 적어 두시기 바랍니다. 제 경우에는 여섯 줄 전부가 2027년 1월 15일에 한꺼번에 만료됩니다. 가입일로부터 약 6개월이라 길어 보이지만, 느긋하게 진행하다 보면 크레딧이 남은 채로 사라지기에 충분히 짧은 기간입니다.


### 예전의 12개월 무료와는 구조가 다릅니다


AWS를 예전에 써 보셨거나 오래된 글을 보고 오신 분이라면 이렇게 알고 계실 것입니다. 새 계정은 12개월 동안 작은 서버와 작은 데이터베이스가 공짜라고요. 2025년 7월 이후에 만든 계정은 그렇지 않습니다. 정해진 항목이 공짜인 방식에서, 현금처럼 쓰는 크레딧을 주는 방식으로 바뀌었습니다. 저도 반신반의해서 아래 명령으로 무료 항목이 무엇인지 직접 확인해 봤습니다.


```bash
aws freetier get-free-tier-usage
```


결과에 RDS는 없었고, 실제로 초반에 RDS를 잠깐 썼을 때도 할인 없이 단가 그대로 크레딧에서 빠져나갔습니다. 그러니 무엇이 공짜인지를 외울 필요 없이, 무엇을 쓰든 크레딧에서 차감된다고 생각하시는 편이 안전합니다. 이 변화는 ⑨편에서 실제 선택으로 이어집니다. 관리형 RDS 대신 클러스터 안에 Postgres를 직접 띄우기로 한 판단이 바로 여기서 출발합니다. 한 가지 예외로 ①편에 적은 대로 제 청구서에서 노드 요금만은 \$0로 찍혔는데, 그 이유는 아직 확인하지 못했습니다.

## 로그인 방식을 고르는 화면에 크레딧이 걸려 있습니다


이제 이번 편에서 가장 중요한 부분입니다. 계정을 만들면 처음에는 루트 계정으로 로그인하게 됩니다. 그리고 곧 루트 계정으로 계속 작업하면 안 된다는 안내를 받습니다. 맞는 말인데, 그러면 무엇으로 로그인해야 할까요?


AWS가 요즘 권하는 답은 IAM Identity Center입니다. 검색해도 이쪽이 먼저 나오고, 콘솔에도 큼직한 Enable 버튼이 있습니다. 저도 권하는 대로 Identity Center를 켜려고 했습니다. 그런데 마지막 확인 화면에 이런 문장이 있었습니다.

> Creating an organization automatically upgrades your account from a free plan to a paid plan with a pay-as-you-go pricing and **your free tier credits expire immediately.**

조직(Organizations)을 만들면 계정이 무료 플랜에서 유료 플랜으로 자동 승격되고, 프리티어 크레딧은 즉시 만료된다는 뜻입니다. 로그인 방식을 고르는 중인데 왜 조직 이야기가 나올까요? IAM Identity Center가 내부적으로 AWS Organizations를 필요로 하기 때문입니다. 아래 그림은 버튼 하나에서 크레딧까지 이어지는 경로를 순서대로 보여 줍니다. 첫 번째 칸에서 네 번째 칸까지 몇 단계나 떨어져 있는지 세어 보시기 바랍니다.


![Anim.4 — Identity Center를 켜면 조직이 만들어지고, 계정이 유료 플랜으로 바뀌고, 크레딧이 만료됩니다. 그림은 AI가 코드로 그렸습니다](https://dhbang.co.kr/images/aws-eks/anim04-credit-chain.svg)


이것은 버그가 아니라, 크레딧이 무료 플랜에 딸린 혜택이라서 유료 플랜으로 올라가면 근거가 사라지는, 설계대로의 동작입니다. 문제는 원인과 결과가 세 단계나 떨어져 있다는 데 있습니다. Enable 버튼 어디에도 크레딧 이야기는 없고, 경고는 확인 화면까지 가야 보입니다. 게다가 Identity Center 첫 화면의 기본 Enable 버튼도 같은 경로로 이어집니다.


⚠️ 그래서 이 시리즈를 진행하는 동안에는 Identity Center를 아예 켜지 않으시기를 권합니다. 한 가지 덧붙이면, 저는 그 확인 화면에서 Enable을 누르지 않고 취소했기 때문에 실제로 크레딧이 사라지는 것을 직접 본 것은 아닙니다. 제가 확인한 것은 그 화면에 그렇게 적혀 있다는 사실까지입니다. 그래도 \$200을 걸고 시험해 볼 일은 아니라고 판단했습니다.


### 그래서 IAM 사용자와 액세스 키를 씁니다


그러면 로그인은 무엇으로 할까요? 조직을 만들지 않는 예전 방식으로 돌아갑니다. IAM 사용자를 하나 만들고 액세스 키를 발급받는 방식입니다. 요즘 권장되는 방법은 아닌데, 키가 유출되면 그것으로 끝이고 스스로 만료되지도 않기 때문입니다. 하지만 혼자 쓰는 학습 전용 계정에서는 크레딧을 잃을 위험이 없다는 점이 더 중요하다고 판단했습니다.


이 부분은 콘솔에서 해야 합니다. 콘솔 검색창에서 IAM을 찾아 들어간 뒤 사용자 메뉴에서 사용자를 하나 만듭니다. 이름은 자유롭게 정하시면 되고, 권한을 정하는 단계에서는 정책을 직접 연결하는 방식을 골라 `AdministratorAccess`를 붙입니다. 사용자가 만들어지면 그 사용자의 보안 자격 증명 탭에서 액세스 키를 만드는데, 용도를 묻는 화면에서는 명령줄 인터페이스(CLI)를 고릅니다. 콘솔의 메뉴 이름과 위치는 가끔 바뀌므로, 이름이 조금 달라도 같은 흐름을 찾으시면 됩니다.


여기서 하나만 주의하시면 됩니다. 액세스 키를 만들면 키 ID와 시크릿 두 가지가 나오는데, 시크릿은 그 화면에서 딱 한 번만 보여 줍니다. 화면을 닫기 전에 아래 명령을 실행해서 내 컴퓨터에 등록해 두세요. 실행하면 네 가지를 차례로 묻습니다.


```bash
aws configure
```


```plain text
AWS Access Key ID     [None]: <발급받은 키>
AWS Secret Access Key [None]: <발급받은 시크릿>
Default region name   [None]: ap-northeast-2
Default output format [None]: json
```


리전은 서울(`ap-northeast-2`)로 맞춰 주시기 바랍니다. 이 시리즈에 나오는 비용 수치가 전부 서울 리전 기준이어서, 다른 리전을 쓰시면 금액이 조금씩 달라집니다.


권한을 전부 주는 것이 마음에 걸리실 수 있습니다. 저도 그랬지만, 권한을 좁히려면 EKS, VPC, IAM, ECR, ACM에 걸쳐 수십 개의 동작을 일일이 허용해야 합니다. 그러다 어딘가에서 막히면 원인이 권한인지 코드인지 구분하는 데 시간을 다 쓰게 됩니다. 이 계정은 학습 전용이고 실제 서비스가 올라가지 않으므로, 배우려는 대상이 IAM 정책 설계가 아니라면 여기서는 넓게 주는 편이 낫다고 봤습니다.


대신 이 키는 비밀번호처럼 다루셔야 합니다. 코드에 적지 말고, 커밋하지 말고, 어디에도 붙여넣지 않습니다. 키는 `~/.aws/credentials`에만 있어야 하고, 실습이 전부 끝나면 삭제합니다. 삭제는 ⑫편의 정리 목록에 넣어 두었습니다. 이제 계정이 제대로 연결됐는지 확인해 봅니다.


```bash
aws sts get-caller-identity
```


```json
{
  "UserId": "AIDA...",
  "Account": "123456789012",
  "Arn": "arn:aws:iam::123456789012:user/<만든 사용자 이름>"
}
```


`Arn`의 끝에 방금 만든 사용자 이름이 보이면 연결된 것입니다. 앞에서 실패했던 확인 명령도 이제는 끝까지 통과합니다.

## 잔액을 평범하게 조회하면 "아직 안 썼네"로 읽힙니다


마지막으로 익혀 둘 것이 하나 있습니다. 크레딧을 얼마나 썼는지 확인하는 방법입니다. 앞으로 실습할 때마다 보게 될 텐데, 평범하게 조회하면 거의 항상 \$0에 가까운 숫자가 나옵니다. 이 숫자만 보면 아직 아무것도 안 썼다고 읽기 쉽습니다. 정말 그럴까요?


그렇지 않고, 사용액과 크레딧 차감액이 같은 달 안에서 서로 지워진 결과입니다. 예를 들어 \$0.33을 쓰면 크레딧에서 \$0.33이 빠지므로, 둘을 합친 순액은 \$0.00000004 같은 값이 됩니다. 숫자 자체는 맞지만 우리가 알고 싶었던 것은 아닙니다. 쓴 돈을 보려면 둘을 분리해서 조회해야 합니다.


```bash
aws ce get-cost-and-usage --time-period Start=2026-07-01,End=2026-07-29 \
  --granularity MONTHLY --metrics UnblendedCost \
  --filter '{"Dimensions":{"Key":"RECORD_TYPE","Values":["Usage","Credit"]}}' \
  --group-by Type=DIMENSION,Key=RECORD_TYPE
```


```plain text
Usage    0.3282654451
Credit  -0.3282654047
```


위쪽이 실제로 쓴 금액이고 아래쪽이 크레딧에서 빠진 금액입니다. 우리가 보고 싶은 것은 `Usage` 쪽입니다. `RECORD_TYPE`으로 나누지 않으면 두 값이 합쳐져서 순액만 나오므로, \$200 중 얼마를 썼는지 보려면 이 필터를 꼭 넣으셔야 합니다. 한 가지 주의할 점은 이 조회 명령이 한 번에 1센트씩 과금된다는 것입니다. 자주 돌릴 필요는 없고, 실습을 마친 다음 날 한 번 확인하는 정도면 충분합니다.

## 준비가 끝났다고 안전해진 것은 아닙니다


여기까지 하면 계정을 쓸 준비는 끝납니다. 그러면 이제 클러스터를 만들어도 될까요? 아직은 이른데, 지금 상태에서 무언가를 켜 놓고 잊으면 아무도 알려 주지 않습니다. 예산 알림이 없으니 크레딧을 다 쓸 때까지 조용하고, 이상 지출을 감지하는 장치도 아직 제대로 설정되지 않았기 때문입니다.


다음 편이 ④편의 네트워크가 아니라 ③편의 가드레일인 이유가 여기에 있습니다. 첫 과금은 ⑤편에서 시작되고, 그 전의 편들은 전부 준비에 씁니다. 순서를 바꿔서 클러스터부터 만들어 보고 싶어지실 수도 있습니다. 하지만 저는 가드레일의 절반을 첫 과금 뒤에야 갖췄습니다. 예산 알림은 미리 만들어 뒀지만 이상 지출 탐지는 첫 클러스터를 띄우고 닷새 뒤에야 넣었고, 그 사이에는 지킬 장치 하나가 빠진 채로 과금이 나가고 있었습니다.


액세스 키를 쓰는 지금 방식도 어디까지나 임시라는 점을 다시 말씀드립니다. 혼자서 내 컴퓨터에서만 쓰는 동안에 한해 받아들일 만한 타협이고, 팀으로 쓰거나 실제 서비스를 올릴 계정이라면 이렇게 하면 안 됩니다. 그런 계정에서는 크레딧보다 보안이 중요하므로 Identity Center를 쓰는 것이 맞습니다.

## 정리


| 한 것                | 확인 방법                              |
| ------------------ | ---------------------------------- |
| 도구 네 개 설치          | `command -v tofu kubectl aws helm` |
| 크레딧 구성 파악          | 기본 \$100 + 활동 \$20×5, 만료일 기록         |
| Identity Center 회피 | 켜지 않은 상태 유지                        |
| IAM 사용자 자격증명       | `aws sts get-caller-identity`      |
| 사용액 조회법            | `RECORD_TYPE`으로 Usage와 Credit 분리   |


가장 비싼 실수가 가장 싼 단계에 숨어 있었습니다. 이번 편은 돈이 한 푼도 나가지 않지만, \$200을 통째로 잃을 수 있는 유일한 편이기도 했습니다. 그 함정만 피했다면 나머지는 설치와 확인의 반복입니다.


다음 편에서는 예산 알림과 이상 지출 탐지를 콘솔이 아니라 코드로 만듭니다. 콘솔로 하면 3분이면 끝나는 일을 굳이 코드로 하는 이유도 함께 다루겠습니다.
