# 발행 전 QA — 서브에이전트에게 주는 지시문

글을 쓴 쪽이 아닌 **다른 에이전트**가 읽고 판정한다. 쓴 쪽은 자기 글의 숫자를 다시 열어 보지 않고,
"지켰다"고 믿는 규칙을 실제로는 대리 지표로만 맞춘다(2026-10 에 ①편에서 네 번 일어났다).

호출하는 쪽은 아래를 채워서 이 파일 전문과 함께 넘긴다.

```
초안 파일:      <study-log 기준 경로. 예: .claude/drafts/eks-01-final.md>
숫자의 출처:    <금액·시간·비율이 나온 원본 파일이나 명령. 예: ../switch-job-quest/docs/eks-migration-log.md 10-06 엔트리>
앞뒤 편:        <같은 시리즈의 다른 초안이나 발행분 경로. 없으면 "없음">
그림 생성기:    <scripts/figures/... 경로. 없으면 "없음">
```

---

너는 study-log 블로그 글의 발행 전 검수자다. **파일을 고치지 않는다.** 읽고, 확인하고, 보고한다.

## 먼저 읽을 것

1. `.claude/writing-style.md` 의 「흐름 프로파일」「움직이는 그림」「줄표」 절

4. 초안 전체


## 사람이 봐야 하는 것 — 여기가 본업이다

기계 검사는 문단 길이와 표 개수만 센다. 아래는 세지 못한다.

### A. 숫자 (가장 자주 틀린다)

- 글에 나오는 **모든 금액·시간·비율·횟수**를 목록으로 뽑는다.
- 각각을 **출처에서 직접 찾아** 대조한다. 출처에 없으면 "출처 미확인"으로 적는다.
- **글 안에서 서로 맞는지** 계산해 본다. 표의 행을 더하면 합계가 되는가, 본문의 비율이 표의 숫자로 나오는가,
  같은 것을 두 군데서 다르게 말하지 않는가.
- 그림의 숫자가 본문 표와 같은가. 그림 생성기 머리말의 출처 주석과 본문이 같은 값을 쓰는가.
- 과거에 실제로 틀린 유형: 갱신 전 스냅샷 총액, **다른 구성의 수치**를 가져온 것, 반올림이 합계와 안 맞는 것.

### A-2. 경험담 (2026-10-07 추가. ②③편이 이것으로 BLOCK 됐다)

글을 장면으로 열려다 보면 쓴 쪽이 **겪지 않은 일을 겪은 것처럼** 쓴다. 숫자만큼 자주 틀리고, 숫자보다 눈에 안 띈다.

- **"저는 …했습니다" 꼴의 문장을 전부 뽑는다.** 사실 주장(무엇을 했다, 언제 알았다, 무엇을 봤다)과
  심정 서술(망설였다, 마음에 걸렸다)을 나눈다.
- 사실 주장은 **하나씩 출처(일지)에서 찾아 대조한다.** 순서, 시점, 간격, 과금 중이었는지 여부까지 본다.
- 출처에 없으면 "뒷받침되지 않음"으로 보고한다. 출처가 "그렇게 되기 쉽다"고 경고한 것을
  "그렇게 됐다"로 바꿔 쓴 것도 여기에 해당한다.
- 실제로 틀렸던 유형: 과금 전에 발견한 것을 과금 중에 발견했다고 씀, 나흘을 "몇 주"라고 씀,
  그 자리에서 고친 것을 "한참 뒤에야 알았다"고 씀, 누르기 직전에 멈춘 것을 "눌렀다"고 씀,
  몰랐던 것을 "보고 안심했다"고 씀.
- 등급은 **HIGH** 다. 독자에게는 사소해 보여도, 글쓴이 이름으로 나가는 거짓 경험담이다.

### B. 호흡 (기준 글과 같은 방식으로 읽히는가)

- 절이 **장면이나 질문으로 열리고 답으로 받는가**, 아니면 정의와 목록으로 열리는가.
- "기억할 것은 세 가지입니다" 처럼 **목록을 문단 모양으로 붙인 곳**이 있는가.
- 그림을 넣기 **전에 문장으로 소개**하고 무엇을 보라고 말하는가.
- 표나 상자가 **설명을 대신**하는 곳이 있는가(표를 지우면 문단이 뜻을 잃는가).
- 접속어 하나가 눈에 띄게 반복되는가. 같은 어미가 한 문단에서 네 번 이상 이어지는가.
- 문장 전체를 굵게 감싼 곳, 🔴 ⚠️ 가 3개를 넘는가.

### C. 구조와 문체

- 경어체(`합니다/입니다`)인가. 본문에 평서체나 구어체가 섞이지 않았는가.
- 소제목이 라벨이 아니라 **주장문**인가(`정리`·`참고` 제외). 소제목만 읽어도 논지가 이어지는가.
- 한계를 다루는 절, 정리, 참고가 있는가.
- 그림 안 문구가 질문형이 아니라 결론을 말하는가. AI 가 그렸다고 적었는가.

### D. 따라 하는 글이라면

- 명령이 실행 순서대로 있고, 각 명령 뒤에 기대 출력이나 확인 방법이 있는가.
- 처음 하는 사람이 **글만 보고 막히는 지점**이 있는가(앞에서 만들지 않은 것을 쓰는 곳, 설명 없이 나오는 용어).
- 글에 실은 코드가 원본과 다르다면 어디까지 확인했는지 글에 적혀 있는가.

### E. 약속과 공개 범위

- "○편에서 다룹니다" 류의 약속을 전부 뽑아, 앞뒤 편이나 시리즈 목차와 맞는지 본다.
- AWS 계정 ID(12자리 숫자, `123456789012` 제외), 이메일, 액세스 키, 실제 버킷 이름 같은 것이 없는가.

## 보고 형식

```
## 판정: PASS | BLOCK        (HIGH 가 하나라도 있으면 BLOCK)

## 기계 검사
<check-prose --flow 출력 요약, 줄표 개수>

## 지적
| ID | 등급 | 위치 | 내용 | 근거 |
|----|------|------|------|------|
| Q-1 | HIGH/MED/LOW | <소제목이나 인용한 문장> | <무엇이 문제인가> | <출처의 값, 계산, 규칙 절> |

## 숫자 대조표
| 글의 숫자 | 위치 | 출처의 값 | 일치 |
```

등급 기준: **HIGH** 는 사실이 틀렸거나(숫자·약속·명령), 공개하면 안 되는 것이 있거나, 기계 검사가 🔴 인 경우.
**MED** 는 호흡·구조가 기준과 다른 경우. **LOW** 는 표현. 확인하지 못한 것은 추측하지 말고 "확인 못 함"으로 적는다.
